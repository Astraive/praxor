# Query ownership and current readiness

Astraive/praxor owns the canonical query semantics in package `praxis`:
tokenization, syntax, binding/type rules, logical models, planning, execution
and semantic catalog rules. These responsibilities sit above the engine's
low-level storage kernel. This is the ownership direction, not a claim that
every stage or language feature is implemented. The query, planner, execution
and semantic catalog modules retain the experimental status stated in
`src/lib.rs`; Q0 does not promote them to stable APIs.

| Owner | Responsibility and dependency direction |
| --- | --- |
| Praxor engine (`praxis`) | One semantic pipeline and catalog authority over storage primitives. Depends on neither Poiesis nor optional PQL tooling. |
| Poiesis | Product/session context, authorization, protocol handling and runtime orchestration; consumes engine contracts. |
| Optional PoiesiSQL/PQL tooling | Editors, CLI, explain presentation and SDK assistance using engine contracts; no second authoritative compiler or catalog writer. |
| Pit | Separately reviewed durable version-history capability; no query history is implied by its existence. |
| Poietica | Product API consumer; no storage ownership follows from UI integration. |

The dependency graph remains acyclic. A clean engine checkout builds by itself;
Q0 adds no required sibling checkout, absolute-path dependency, crate rename or
import from preserved dirty sources. Storage APIs and product protocols retain
their existing constructors and ownership. See [architecture](architecture.md),
[storage source ownership](storage-source-ownership.md) and
[Q0 #60](https://github.com/Astraive/praxor/issues/60).

## Public compatibility observations

The tests were first executed on merged F2 default
`259c6a6b9523879c6ee8733151ddd38cc8f988f4` with Rust 1.99.0, before these prose
changes. All 15 new tests passed on that first run. They preserve representative
current import/serde observations, not an exhaustive stable wire protocol:

- `query_public_contract` checks root and module exports, parser/planner/helper
  signatures, provider trait reachability and current serde model bounds.
- `query_serde_contract` compares six checked-in literal JSON fixtures with
  independently constructed logical, physical, clause, CTE and cost values.
  Literal fixture expectations are not generated by the parser or planner.
  Object ordering/whitespace is irrelevant; operator ordering matters. Missing
  optional `as_of` decodes to None; missing required `params` fails decoding.
- `query_readiness_characterization` executes a small in-memory document
  provider. It asserts literal row IDs rather than timestamp-bearing
  full-record snapshots. It is not a durable storage or retained-view adapter.

The executor's `document::RecordId { collection, key }`, core
`store::RecordId(u64)` (also the root reexport) and page `identity::Rid` are
distinct types and domains. Matching names or numeric values authorize no
conversion. Likewise, the in-memory semantic `catalog::schema::Catalog` differs
from the page-backed `catalog::CatalogStore`. Serde reachability establishes no
persisted catalog transaction.

Costed model fields have representative literal coverage. A reason string is
diagnostic data, not a new stable explain-text contract. The planner check
asserts a bounded finite estimate and operator shape; it does not snapshot all
cost reasons, floating formatting or EXPLAIN prose.

## Readiness matrix

“Executed” below means the named Q0 public test ran against a tiny in-memory
provider, not against CoreDatabase or a product endpoint. “Source-reviewed”
means the current implementation was inspected without claiming a behavioral
execution check for that row.

| Path | Current observation | Evidence and readiness limit |
| --- | --- | --- |
| Collection SELECT/filter/order/offset/limit | A bounded numeric predicate returns `u34,u21`; its literal scalar-index result matches the scan fallback. AND/OR has a separate literal result. | Executed. No complete SQL, general acceleration parity, projection or durable backend claim. |
| Projection / scalar SELECT | `SELECT age` and `SELECT *` produce equal logical plans. No-FROM syntax selects `_scalar`. | Projection equality executed; scalar target source-reviewed. Neither proves expression evaluation. |
| `IS NULL` | Parser emits `is_null`; executor returns no rows even with explicit null/missing attributes. | Executed known gap, not SQL null conformance or a capability refusal. |
| PQL `AS OF` | Logical selector survives parsing. Legacy planning now refuses it; a manually constructed `AsOf` physical plan refuses before reading the provider. | Pre-fix executed current-row gap and post-fix refusal are tested in #61. No retained read view, historical payload or durable branch-history binding. |
| `GROUP BY` / aggregates | Legacy planning now refuses `GROUP BY`; a manually constructed GroupBy physical plan refuses before reading the provider. Planner still does not populate Aggregate from SQL SELECT. | Pre-fix ignored behavior and post-fix refusal are tested in #61. Manual Aggregate serde coverage is not SQL aggregation support. |
| Parameters | Ordinary parse_with_params loses supplied metadata; WITH keeps it only on the outer plan. `$`, `:`, `@` placeholders are tokenizer errors. The separate substitution helper replaces raw text, including quotes and `$1` prefixes inside `$10`. | Executed observations. No typed binding or supported placeholder protocol. |
| Trailing tokens / real rejection | Trailing `GARBAGE` can be accepted. Unsupported starting syntax/SHOW target and unterminated quote produce actual Query errors. | Executed. Accepted-but-ignored input is distinct from deterministic refusal. |
| CTE / window models | Boxed CTE/window serde forms are reachable. CTE resolution is not wired into execution; SQL parsing does not call the exported window helper. | Serde/import coverage executed; missing execution/lowering source-reviewed. |
| DML / collection DDL | Public models carry mutations/DDL. Ordinary physical planning ignores operation/mutation/DDL; a separate in-memory RecordStore mutation entrypoint exists. | Model serde executed; dispatch behavior source-reviewed. No SQL transaction, catalog validation or atomic persisted DDL/data claim. |
| EXPLAIN / ANALYZE | Explain formats planner estimates; ANALYZE is retained metadata with no measured execution here. | Source-reviewed. Cost reason prose remains diagnostic. |
| GraphQL / REST query paths | Public GraphQL response contains plan JSON under records. Private REST query handler also returns a plan-shaped record. | GraphQL executed; REST source-reviewed (`src/api/server/rest.rs`), not publicly invoked by Q0. Neither establishes stored-row execution. |
| Full-text/vector/graph/ranking | Models and executor arms exist outside the bounded SELECT corpus. | Source-reviewed only here; no general feature or accelerator-equivalence claim. |
| Storage read seam | Existing RecordProvider reads return infallible Vec/Option. Core record reads can fail and share owner health. | Source-reviewed. Q0 supplies no adapter that hides errors or fabricates empty results. |

Remaining accepted-but-ignored cases are explicitly named `known_gap_*`
characterization. They record current limitations, not supported semantics
that must be retained. #61 changes only the AsOf/GroupBy legacy refusal;
direct old execution is still experimental. Q0 made no production parser,
planner, executor or backend correction and manufactured no RED; the #61
behavioral tests were run against Q0 source before the refusal change.

## Follow-on gates

[Q1 #61](https://github.com/Astraive/praxor/issues/61) owns bounded canonical
SELECT/filter compilation, real typed parameters and deterministic capability
rejection of ignored features. Existing candidate behavior defects require
actual pre-fix behavioral evidence; parser/plan success alone is insufficient.

[Q2 #62](https://github.com/Astraive/praxor/issues/62) owns a fallible retained
read-view backend after the appropriate record-authority/snapshot gates. A
raw mapping ceiling or a future F3 process-local token does not by itself bind
query AS OF selectors or establish Pit's durable history semantics.

[Q3 #63](https://github.com/Astraive/praxor/issues/63) first designs, then proves
one persisted catalog DDL/data atomic operation after Q1/Q2. The current
semantic catalog's serde and separate page catalog are not that protocol.

Runtime adoption reuses [Poiesis #5](https://github.com/NeerajCodz/poiesis/issues/5);
optional PQL adoption reuses [PoiesiSQL #2](https://github.com/Astraive/poiesisql/issues/2).
No duplicate pipeline, catalog writer or required integration is introduced by
Q0. Durable history, page migration, product routing and ecosystem completion
retain their separate verification gates.
