The public `QueryGateway::attach_fixture_v1` attaches a fixed, process-local Loose Q1 catalog to an already-open `CoreDatabase` for a declared PRXQDOC-NUL v1 fixture root. `begin_read` pairs a catalog view with one existing F3 core snapshot pin; clones share that pin. `query` compiles a bounded Q1 SELECT or returns value-free EXPLAIN. The SELECT path scans every visible State entry and each live Payload at that retained view, reconciles live count and bytes against the same-pin allocator, decodes every live fixture envelope (including other collections), rejects duplicate requested `{collection,key}` pairs, and delegates complete requested-collection rows to Q1's evaluator. It validates owner/catalog/bound authority before I/O and again before success and returns typed storage, document, compile and resource errors without partial Rows.

The production acceleration backend returns `Unavailable`; it uses the held-view complete scan. A private, test-only synthetic `Ready` backend certifies ordered `(physical RID, full Record)` candidate equality against a fresh complete same-view scan before selecting a candidate. This is a seam/equivalence test, not a maintained index or speedup. The catalog is not persisted or atomically versioned with data; there is no product protocol routing, general document format, durable history/AS OF, live scalar index, or SQL/NoSQL/vector feature claim. Fixture limits (including 65,536 candidate keys, 16,384 live rows, 32 MiB scanned payload and 64 MiB conservative logical output) do not bound lower resolver retained-chain allocation, peak memory or latency.
